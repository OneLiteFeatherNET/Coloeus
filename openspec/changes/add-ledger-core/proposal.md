# Proposal

**Ships as:** `feat(ledger)` — one code pull request `feat(ledger): add double-entry ledger service`.
The Kubernetes rollout is a separate pull request in `Kubernetes-FLUX`, not part of this repository.

## Why

Every Paper server on the network keeps its own economy today. A player has a different balance on every server, money
cannot move between servers, and Minestom games, the Velocity proxy and other services have no shared place to credit or
debit a player. Nobody can say who created, moved or destroyed how much money.

Coloeus becomes the one place that holds money for the whole network. This first change builds the core that every later
client depends on: currencies, one account per player, an append-only double-entry journal, and atomic, idempotent
transactions behind an HTTP API that services reach with Entra ID tokens. Requirements and decisions are in Outline
("Anforderungen: Coloeus", stage 1) and the architecture proposal.

## What Changes

- **Currencies** with code, singular/plural name, symbol and a fixed number of fraction digits; exactly one default
  currency (the one the Vault bridge will serve). Fraction digits never change after creation.
- **Accounts**: one network-wide account per player, created automatically on first access by UUID, also for players who
  were never online. System accounts per client (`SOURCE`, `SINK`) and per currency (`FEE`, `ADMIN_SOURCE`,
  `ADMIN_SINK`) are created on demand.
- **Journal**: every money movement is a transaction of postings whose sum per currency is zero. Transactions and postings
  are insert-only; corrections are new transactions. Balances are a projection updated in the same database
  transaction.
- **Transactions**: `TRANSFER` between accounts, `MINT` (credit a player against the client's source account), `BURN`
  (debit a player into the client's sink account) and `BATCH` (several postings that succeed or fail together), each
  with reason, actor, external reference and up to 16 metadata entries. No balance may fall below zero in this change;
  configurable overdraft limits, fees and limits follow in `add-ledger-rules`.
- **Idempotency**: every write requires an `Idempotency-Key`; a repeat with the same body returns the original result, a
  repeat with a different body is rejected with 409. Keys are kept per client for at least 7 days.
- **Money as JSR 354**: the domain uses `MonetaryAmount` (Moneta `Money`, `DECIMAL128`) and Coloeus `CurrencyUnit`s from a
  database-backed `CurrencyProviderSpi`. Conversion happens only in the database mapper (`NUMERIC(38, scale)`) and the
  JSON mapper (decimal string); an architecture test enforces this. Incoming amounts with too many fraction digits are
  rejected, never rounded.
- **Authentication**: Entra ID bearer tokens. Services need the app role `Coloeus.Client`; currency and client management
  needs `Coloeus.Admin`. The token's client ID (`azp`) links a service to its registered permissions per currency
  (`MINT`, `BURN`, `TRANSFER_ON_BEHALF`, `READ`).
- **Player names**: a name register with history, fed by join reports; unknown names are resolved through the Mojang
  profile API. Needed for `/pay` and Vault name lookups to offline players.
- **History**: postings of an account, newest first, cursor-paginated.
- **Problem Details** (RFC 9457) with a stable `code` for every error (`INSUFFICIENT_FUNDS`, `SCALE_EXCEEDED`,
  `CURRENCY_UNKNOWN`, `PLAYER_UNKNOWN`, `IDEMPOTENCY_CONFLICT`, `FORBIDDEN_GRANT`, …).
- **Operations**: Postgres with Flyway (forward-only), liveness/readiness health endpoints, configuration only from
  environment variables, startup fails on missing tenant, audience or database; OpenTelemetry traces and logs.

## Capabilities

### New Capabilities

- `currencies`: currency definitions, default currency, JSR 354 currency provider.
- `accounts`: player and system accounts, automatic creation, balances.
- `ledger-transactions`: transfer, mint, burn, batch; journal invariants; history.
- `idempotency`: idempotent writes.
- `service-auth`: Entra ID tokens, app roles, client registry and grants.
- `player-names`: name register and Mojang resolution.
- `problem-details`: error format and codes.

### Modified Capabilities

None (first change).

## Impact

- New module content in `backend` (API, domain, persistence, Flyway migrations, tests with Testcontainers Postgres).
- New dependencies: Micronaut Data JDBC, Flyway, Postgres driver, Moneta, Micronaut Security JWT, Testcontainers,
  ArchUnit.
- OpenAPI document generated by the backend; the Java client follows in `add-java-client`.

## Out of scope

Fees, limits, overdraft and frozen accounts (`add-ledger-rules`); balance events, SSE, metrics and reconciliation
(`add-balance-events`); Java client (`add-java-client`); Vault bridge, Velocity commands, admin web and staff actions
(later changes); Kubernetes manifests (`Kubernetes-FLUX`).
